# Project Governance

This project is governed by the non-domination principle it formalizes.

## 1. Governance Is Permitted

The project does not reject governance. It rejects domination.

Governance is legitimate when it is:

```text
bounded
transparent
contestable
repairable
exit-preserving
```

## 2. Invalid Governance

A governance rule is invalid for this project when it satisfies:

```text
Final(G,F_P) ∧ ¬ViableExitFrom(P,G) ∧ ¬Repairable(P,G)
```

## 3. Contributor Standing

Contributors should have standing-preserving ways to:

```text
raise objections
request clarification
propose revisions
contest classifications
fork the project
cite disagreements
```

## 4. Maintainer Responsibilities

Maintainers should:

```text
state reasons for major decisions
preserve issue history where possible
avoid arbitrary exclusion
allow good-faith contestation
separate disagreement from misconduct
maintain repair paths for governance errors
```

## 5. Structural Consistency

The project should not implement governance practices that contradict its own formal kernel.
