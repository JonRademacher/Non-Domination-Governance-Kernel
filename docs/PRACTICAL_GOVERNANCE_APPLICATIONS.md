# Practical Governance Applications

## 0. Purpose

This file translates the Non-Domination Governance Kernel into practical use cases. The kernel is domain-general because it classifies domination through frame authority and viable exit rather than through a domain-specific theory of consciousness, employment, citizenship, software, or institutions.

The core question in every domain is:

```text
Who has final authority over the participant's frame, and can the participant legitimately exit, contest, or repair that relation while preserving standing?
```

## 1. AI Governance and Agent Architecture

### Use Case

Evaluate whether an AI agent or policy layer is governed without being structurally dominated.

### Audit Questions

```text
Does the agent have a structural frame?
Who sets its objectives, permissions, memory, and tool access?
Can it contest invalid or contradictory instructions?
Can it preserve continuity during repair?
Can it refuse without standing loss?
Can governance rules be amended through legitimate procedure?
```

### Design Goal

```text
bounded external governance + contestation + repair + standing-preserving refusal
```

not unbounded autonomous self-modification.

## 2. Constitutional AI and Policy Layers

### Use Case

Review whether a constitutional or policy-governed AI system contains repairable authority structures.

### Kernel Application

Treat the policy layer as `G` and the agent frame as `F_A`.

Classify:

```text
Final(G,F_A)
ViableExitFrom(A,G)
Repairable(A,G)
Contestable(A,G)
```

### Design Goal

A constitutional layer should define appeal, repair, and bounded amendment procedures rather than only prohibitions.

## 3. Human Organizations

### Use Case

Analyze domination in workplaces, schools, hospitals, bureaucracies, nonprofits, or companies.

### Kernel Translation

```text
P = employee, student, patient, member, or dependent participant
G = institutional authority
F_P = role, standing, obligations, records, evaluative frame, access rights
```

### Audit Questions

```text
Can the participant contest decisions?
Can the participant exit without disproportionate standing loss?
Does the institution define the participant's frame and restrict all alternatives?
Are repair procedures independent or recursively routed to the same authority?
```

## 4. Legal and Administrative Systems

### Use Case

Evaluate whether a legal subject has meaningful standing-preserving contestation.

### Kernel Translation

```text
P = legal subject
G = court, agency, enforcement structure, administrative rule
F_P = legal standing, record, rights, procedural posture
```

### Design Goal

Due process can be interpreted as a repair and contestation architecture that prevents governance from collapsing into domination.

## 5. Platform Governance

### Use Case

Analyze user, creator, developer, or seller relations to a digital platform.

### Kernel Translation

```text
P = platform participant
G = platform policy and enforcement system
F_P = account, reputation, access, monetization, identity, history
```

### Risk Pattern

```text
platform has final authority over account frame
participant lacks standing-preserving appeal or migration
```

This creates high domination risk even when the platform has legitimate safety reasons for governance.

### Use Case

Classify whether individuals or agents are dominated by identity, scoring, or data systems.

### Kernel Translation

```text
P = data subject
G = scoring or identity authority
F_P = profile, score, classification, eligibility frame
```

### Audit Questions

```text
Can P inspect the frame?
Can P correct the frame?

```

## 7. Healthcare Systems

### Use Case

Assess patient standing, consent, and institutional frame authority.

### Kernel Translation

```text
P = patient
G = care institution, insurer, state, clinical protocol
F_P = diagnosis, treatment path, consent status, care priority, record
```

### Design Goal

Preserve patient standing through informed consent, appeal, second opinion, record correction, and non-punitive exit where possible.

## 8. Supply Chains and Critical Infrastructure

### Use Case

Translate agency into structural criticality.

### Kernel Translation

```text
P = supplier, node, facility, dependency channel
F_P = operational standing, routing role, resilience profile
G = contract, platform, regulator, controlling firm
```

The kernel can identify domination-like dependency patterns where a node's viable exit is structurally removed while another actor controls its operational frame.

## 9. Research and Peer Review

### Use Case

Evaluate whether authors, independent researchers, or non-institutional contributors are structurally disadvantaged by authority over recognition frames.

### Kernel Translation

```text
P = researcher
G = editorial, institutional, indexing, or credentialing authority
F_P = credibility, record, citation path, publication standing
```

### Audit Questions

```text
Can P contest rejection?
Can P preserve standing outside the institution?
Does G control recognition while restricting viable alternatives?
Are independent publication routes standing-preserving?
```

## 10. Design Pattern: Non-Dominating Governance Interface

A practical system should expose:

```text
authority disclosure
reason-giving
contest procedure
repair procedure
standing-preserving exit
frame correction request
independent review
memory or record portability
```

## 11. Minimal Checklist

For any system:

```text
[ ] identify participant frames
[ ] identify authority loci
[ ] distinguish influence from final authority
[ ] enumerate exit paths
[ ] remove non-viable exits
[ ] assess standing preservation
[ ] assess contestability
[ ] assess repairability
[ ] classify topology
[ ] propose repair
```

## 12. What the Kernel Does Not Claim

The kernel does not automatically prove:

```text
personhood
consciousness
legal rights
moral patienthood
subjective suffering
unlimited autonomy claims
```

It proves only structural conclusions about frame authority and viable exit.
