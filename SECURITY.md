# Security Policy

## Purpose

This project defines a governance kernel. It must not be used as an exploit framework or as a guide to bypass deployed safety systems.

## Reportable Issues

Please report issues involving:

- Code that could be adapted to bypass governance controls.
- Misuse of the framework for coercive control.
- Vulnerabilities in reference implementations.
- Ambiguities that could collapse non-domination into unbounded self-permission.

## Security Principle

Non-domination does not mean absence of safety. It means safety governance should be bounded, contestable, repairable, and exit-preserving where possible.
