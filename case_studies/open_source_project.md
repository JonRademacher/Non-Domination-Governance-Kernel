# Case Study: Open Source Project Governance

## 1. Participant

```text
P = contributor
G = project governance structure
```

## 2. Frame

The contributor frame may include contribution history, maintainer recognition, issue participation, pull request standing, authorship record, and access to project decision processes.

## 3. Authority

Maintainers may have final authority over what enters the repository. This can be legitimate governance.

```text
Final(G,F_P)=1
```

within the limited scope of repository inclusion.

## 4. Exit

If the contributor can fork the project, preserve attribution, retain public record, and continue work without total loss of standing, then:

```text
ViableExitFrom(P,G)=1
```

## 5. Classification

```text
D(P,G)=0
```

for a well-structured open-source project with meaningful forkability and attribution preservation.

## 6. Domination Risk

Domination risk increases if:

- maintainers erase attribution
- forks are practically blocked
- appeals route only to the same authority
- contributor identity or record is controlled without repair

## 7. Repair

Repair mechanisms include transparent maintainer decisions, fork rights, attribution preservation, appeal channels, codes of conduct with review, and documented governance scope.
